# assets — アバターのパーツを作るスクリプト

**[avatar.blend.py](./avatar.blend.py) が Blender の中で走り、
`client/assets/` に 4つの `.glb` を書き出す。**

```bash
cd assets && npm install && npm run build
```

2段になっている。

| | |
| --- | --- |
| **生成**（`avatar.blend.py`） | Blender の中で走り、`assets/build/` に4つの `.glb` を書き出す |
| **最適化**（`optimize.mjs`） | [glTF Transform](https://gltf-transform.dev/) で縮めて `client/assets/` に置く |

出力（2026-09-13 実測）:

```
パーツ 83（うち共通 26）  最重の組合せ 1868 三角形  形の組合せ 134,400 通り

avatar-common.glb   306.8 KB → 179.3 KB   骨・3クリップ・髪14・靴5・小物7
avatar-body-0.glb   302.5 KB → 171.3 KB   素体（細め）・トップス10・ボトムス8
avatar-body-1.glb   303.4 KB → 172.1 KB   素体（ふつう）・〃
avatar-body-2.glb   302.5 KB → 171.3 KB   素体（丸め）・〃
合計              1215.1 KB → 694.1 KB  / アバターの取り分 1,229 KB（10 §1）
```

### 何が容量を食っていたか

```
WEIGHTS_0 77KB   POSITION 58KB   NORMAL 58KB   COLOR_0 39KB   indices 27KB
```

**`WEIGHTS_0` が最大だった。** うちのスキニングは剛体（どの頂点も重みは 1,0,0,0）なのに、
`float32 × 4 = 16バイト/頂点` を使っていた。8bit で足りる。法線と色も同じ。これで **43%** 落ちた。

使うのは glTF 標準の `KHR_mesh_quantization` だけ。three.js が追加のデコーダ無しで読める。
Draco も Meshopt もデコーダ（数百KB）の配信が増えるので、削れる量より不利になる。

**生成物はリポジトリに入れてある。** アプリを動かすのに Blender は要らない。
形を変えたいときだけ、Blender を入れてこのスクリプトを走らせ直す。

## 何通りあるか

| | |
| --- | --- |
| 形の組み合わせ | 体型3 × 髪14 × トップス10 × ボトムス8 × 靴5 × 小物8 = **134,400 通り** |
| 配色の組み合わせ | 肌8 × 髪14 × ボトムス10 × 靴6 × 小物10 × 瞳6 = **403,200 通り** |
| パーツ数 | **83**（素体3・髪14・トップス30・ボトムス24・靴5・小物7） |

服の色は**名簿のその人の色**を使う。空間の中で誰がどれか分かるようにするため。

100体並べたところは `/avatar-gallery.html` で見られる。

## なぜ手で作らずスクリプトにしたのか

| 理由 | |
| --- | --- |
| **寸法規約を人手で守らせない** | 1タイル = 1ユニット ≒ 1.0m、+Z が正面（[10 §5](../docs/design/10-assets.md)）。スクリプトが定数として持っている |
| **予算を見ながら形を決められる** | 走らせるたびに最重の組み合わせの三角形数が出る。1,900（[10 §4](../docs/design/10-assets.md)）を超えたら気づく |
| **ライセンスの出所が問題にならない** | 商用可・改変可・**再配布可**（[10 §6](../docs/design/10-assets.md)）を自前で満たす。情シス審査で素材の出所を説明する必要が無い |
| **83パーツを手でモデリングしない** | 髪も服も引数の違い。種類を足すのは表に1行足すだけ |

## 作りの決まり

- **テクスチャを1枚も使わない。** 色は全部 頂点カラー
- **頂点カラーのアルファに「部位ID」を入れる。**
  クライアントはそれを見て人ごとに肌・髪・服を塗り替える（`client/src/avatar.js`）
- **マテリアルは1つ。** クライアントが選んだパーツを統合して描くので **1人 = 1ドローコール**
- **素体は「服の下」も持つが最小限にする。** 胴と腰は必ず服に隠れるので、隙間を埋めるだけ
- 球は滑らかに、円錐と箱はフラットのまま。低ポリらしさを残すため
- 顔の部品（目・まゆ・ほお・口）は `face_y()` で**頭の表面から計算して貼る**。
  手で深さを決めていたときは輪郭から浮いていた
- 前身頃の飾り（前立て・ポケット・合わせ）は `front_y()` で**胴の太さに合わせて置く**。
  固定の深さだと、厚い上着では中に埋もれて見えなかった

## パーツを足すには

表に1行足すだけ。`client/src/avatar.js` の `N` と `client/avatar-preview.html` の
表示名も同じ数にする（`server/test/assets.test.js` が数を検査している）。

```python
HAIR_DEFS = [
    # name,     前髪,        横の長さ, 後ろの量, 追加,       毛量
    ('short',  'straight', 0.95, 0.0, None,       1.00),
    ...
]
```

## 落とし穴（どれも実際に踏んだ）

**1. glTF エクスポータは、マテリアルがアルファを使っていないと COLOR_0 を VEC3 に落とす。**
部位IDはそのアルファに入っているので、落ちると**全員が同じ色で立つ**。
`material()` が `Color Attribute → Alpha → BSDF Alpha` を繋いでいるのはそのためで、消すと壊れる。

**2. 骨の並びが4ファイルで同じでないと手足が飛ぶ。**
クライアントは体型ファイルのジオメトリを共通ファイルの骨に結びつけている。

**3. 位置（POSITION）だけは量子化しない。**
位置を量子化すると、その分を打ち消す変換が**逆バインド行列**に入る。
4ファイルのジオメトリを1つの骨に結びつけて統合するので、
ファイルごとに違う逆バインド行列が入ると手足がずれる。
既定の「メッシュごとに範囲を決める」設定だと、さらに **skin が 1 → 26 に分裂**する。

**4. 小物は髪より外側に置く。**
頭の半径 × 1.2 より内側に置くと、毛量の多い髪型で埋もれる。
最初の版は帽子が髪に沈み、マフラーはあごに隠れて見えなかった。

**5. 靴の寸法は「幅・奥行き・高さ」そのまま。**
一度 2倍で書いてしまい、板のような靴になった。素足は 0.092 × 0.132 m。

## 骨と動き

18本（[10 §4](../docs/design/10-assets.md) の上限）。指も表情も持たない。
**動きは `avatar-common.glb` だけが持つ**（4ファイルに重複させない）。

| クリップ | 長さ | 中身 |
| --- | --- | --- |
| `idle` | 61f (2.0s) | 呼吸で胸と肩がわずかに動く。止まって見えないことが大事 |
| `walk` | 25f (0.8s) | 歩幅 22°。移動速度 4.2タイル/秒 に対して速すぎない |
| `sit` | 61f (2.0s) | 椅子の座面 0.42m に合わせて腰を 0.39m 落とす |

すねの曲げは `walk` と `sit` で**符号が逆**になる（`sit` は腿から見て下へ曲げる）。
最初これを間違えて、足が宙に上がったまま座っていた。
