# client — 実物のクライアント（3D / 2D）

**実サーバ（[../server/](../server/)）に WebSocket でつながる、動くクライアント。**
[../prototype/](../prototype/) が単体で完結した操作プロトタイプなのに対し、
こちらは**位置の正がサーバにある**。手元の座標は予測にすぎない。

```bash
cd ../server && npm install && npm run dev
# → http://127.0.0.1:8787/         本番のクライアント（サーバに接続）
# → http://127.0.0.1:8787/solo.html ひとり用（サーバ無しで動く）
```

**▶ 公開版: [https://claude.ai/code/artifact/c38b8b34-7a92-43ad-b0ac-bbcfc16f2858](https://claude.ai/code/artifact/c38b8b34-7a92-43ad-b0ac-bbcfc16f2858)**

複数人を試すときは別タブで名前を変えて開く。

```
http://127.0.0.1:8787/?name=あかり&body=0
http://127.0.0.1:8787/?name=そら&body=2
http://127.0.0.1:8787/?name=みなと&view=2d   ← 2D ビューを強制
```

> ★ `?u=` `?name=` で本人を名乗れるのは**開発用の仮認証**である。
> 本番は OIDC（[security-review-pack/02 §7](../docs/security-review-pack/02-data-flow.md)）で、
> 差し替えるのは `server/src/adapters/wsServer.js` の1箇所だけで済むようにしてある。

## ひとり用（`solo.html` / `src/solo.js`）

**部屋のロジックはサーバと同じ [`gateway/room.js`](../server/src/gateway/room.js) を、
ブラウザの中で動かしている。**

移動の速度上限も、壁の当たり判定も、着席の4条件も、本番とまったく同じコードが働く。
違うのは「誰が権威か」だけで、ひとりしかいないので権威も自分にある。

```
本番    入力 → WebSocket → Session → Room → tick → WebSocket → 描画
ひとり  入力 →                       Room → tick →              描画
```

同居人はボットで、席を探して座り、しばらくして立ち、ときどきステータスを変える。
「すがた」ボタンでその場で着替えられる（13万通り）。

公開するときは [`make-artifact.mjs`](./make-artifact.mjs) が `solo.html` から中身だけを取り出し、
`.glb` を base64 で1つの `.js` に畳む（**公開先は `.glb` を配信できない**ため）。
画面は `solo.html` が正で、2箇所に書かない。

## 配線

依存は外→内の一方向。逆向きの矢印は無い（[08. 拡張のしかた](../docs/design/08-extensibility.md)）。

```
          /core/*.js            ← サーバと同一ファイル。移動の規則はここにしか無い
             ▲
        src/world.js            論理レイヤー。2Dグリッド上の事実だけ
             ▲        ▲            Three.js も DOM も知らない
   src/render3d.js  src/render2d.js    表現レイヤー。world を読むだけ・書かない
   src/props.js  src/avatar.js         部屋の造作とアバター。three だけを知る
   src/net.js                       トランスポート。ここだけが WebSocket を知る
             ▲
        src/app.js              組み立て口。どの実装を使うかを知る唯一の場所
```

### `/core/` を共有しているのはなぜか

`client/src/world.js` は `/core/movement.js` を読み込む。
これは**サーバが権威判定に使っているのと同じファイル**を、dev サーバがそのまま配っている。

移動の規則が2つ存在すると、予測と権威がずれて「歩いていたら引き戻される」が常態化する。
実装を1つにすれば、ずれる余地は RTT の分しか残らない。

### 何ができるかは論理レイヤーが決める

ボタンの文言も、3D の光る輪も、`world.actionable()` の戻り値1つを見ている。
動詞は **sit / stand / use / knock / walk** の5つだけ（[08 §3](../docs/design/08-extensibility.md)）。

```js
world.actionable()
// → { verb:'sit',   object: <seat> }    席のタイルの上にいる
// → { verb:'use',   object: <note> }    手が届く
// → { verb:'knock', actor: <person> }   近くにいて、集中中でない
// → { verb:'walk',  object: <seat> }    席は見えているが、まだ上に乗っていない
```

**ここがサーバの検証と同じ条件を持っていないと壊れる。**
実際、最初の実装は「手が届けば座れる」にしていたため、ボタンは「ここに座る」と出るのに
サーバは必ず `denied` を返していた（サーバは席のタイルの**上にいること**を求める。[09 §5.2](../docs/design/09-protocol.md) ①）。
この食い違いは単体テストでは出ず、**2つ繋いで動かして初めて見つかった**ので、
[`server/test/gateway.e2e.test.js`](../server/test/gateway.e2e.test.js) に回帰試験を置いてある。

## アバター

**[../assets/avatar.blend.py](../assets/avatar.blend.py) が Blender で生成したパーツを読む。**
テクスチャは1枚も使わず、色はすべて頂点カラーに入っている。

```
src/avatar.js
  loadAvatars()  共通ファイル（骨・動き・髪・靴・小物）＋ 体型3ファイルを1回だけ読む
  lookFor()      userId から見た目を決める。同じ人はいつも同じ姿で出る
  makeAvatar()   選んだパーツを 1つのジオメトリに統合し、部位IDを見て色を塗り替える
```

**種類を増やしてもドローコールは増えない。**
パーツを別メッシュのまま描くと1人あたり6ドローコールになるので、
**統合してから描く**。1人 = 1ドローコール は変わらない。

人数が増えたときに効いてくるのは描画よりも**骨の行列計算**（1人18本ぶんをCPUでやる）なので、

- `Skeleton` は **1人1つだけ**作る（`SkeletonUtils.clone()` は共通ファイルの
  パーツ数ぶん＝26個作ってしまうので使わない。骨だけの雛形を複製する）
- **9タイルより遠い人はアニメーションを3フレームに1回に間引く**（[10 §4](../docs/design/10-assets.md)）

| | |
| --- | --- |
| 形の組み合わせ | 体型3 × 髪14 × トップス10 × ボトムス8 × 靴5 × 小物8 = **134,400 通り** |
| 配色の組み合わせ | 肌8 × 髪14 × ボトムス10 × 靴6 × 小物10 × 瞳6 = **403,200 通り** |
| パーツ数 | **83** |
| 三角形 | 平均 約1,530 / 最重の組合せ 1,868（上限 1,900、[10 §4](../docs/design/10-assets.md)） |
| ボーン | 18 |
| クリップ | `idle` / `walk` / `sit` — 位置の変化と着席状態から選ぶ |
| ダウンロード | 4ファイルで **694 KB**（最適化後。[assets/](../assets/) 参照） |

服の色は**名簿のその人の色**を使う。空間の中で誰がどれか分かるようにするため。
それ以外（肌・髪・ボトムス・靴・小物・瞳）は userId から決まる。

動いているかどうかは**位置の変化**で決める。サーバは「歩いている」を送ってこない
（送る必要が無い。向きと座標があれば分かる）。

着席中は**席の中心に吸い付いて机を向く**。自分の座標のまま座らせると椅子をまたぐ。

モデルは後から届く。**届くまでは簡易表示（カプセル）で動き、読み込みに失敗しても止まらない**
（[10 §9](../docs/design/10-assets.md) の「3Dが落ちても続行する」）。

## 3D と 2D

`app.js` が起動時に一度だけ選ぶ。選んだあとの違いは**見え方だけ**で、論理も通信も同じ。

| 条件 | 起動するもの |
| --- | --- |
| 既定 | `render3d.js`（Three.js 0.186、自己ホスト） |
| WebGL が無い | `render2d.js` に自動で切り替え、その旨を表示 |
| `?view=2d` | `render2d.js` を強制 |

これが「**3D は採用するが必須にしない**」（[10 §9](../docs/design/10-assets.md)）の実体である。

### 描画予算を守るための実装

- 動的な影なし・ポストエフェクトなし。`MeshLambertMaterial` + 3灯（キー・半球・リム）
- 足元の影は**円板を全員ぶん1つの `InstancedMesh`** に畳む（1ドローコール）
- オブジェクトは種別ごとに `InstancedMesh` 1つ
- アバターは1人あたり 本体・頭・名札 の3つ。**人数にしか比例しない**
- 陰は**頂点カラーに焼く**。床の日なた・家具の足元・壁の下側が、光を増やさずに出る
- カメラは固定の斜め見下ろし。回転させない（3D酔いの主因）

### 部屋は `props.js` がコードから組む（`src/props.js`）

机も棚もソファも箱と円柱の組み合わせなので、**glTF を落としてこない**。
ダウンロードは 0 バイトで、形を直すのも速い。骨と動きを持つアバターだけが glTF を要る。

- 家具 **29種**。種別ごとに `InstancedMesh` 1つ
- 壁は `blocked` から生やす。**壁の絵を手で並べない**（表現と論理がずれる）。
  外周は `Grid` が常に塞ぐので、床の広さを決めれば壁は勝手に建つ
- 手前と手前寄りの左右は低く／建てない。**切り取った模型**にしないと中が見えない
- 奥の壁の**裏側にだけ**天井の庇を伸ばす。部屋の上に張ると中身が全部隠れる

> `y ** 0.55` に負の数を入れないこと。頂点は float32 なので床に接する面の y が
> `-7e-10` になることがあり、負の冪乗は `NaN`、`NaN` の頂点カラーは真っ黒に描かれる。
> これで壁が全部黒くなった。`clamp01()` を必ず通す。

### カメラは「部屋が収まる距離」を毎フレーム計算する

俯角 56° 固定。距離は
`min(部屋の幅が画角に収まる距離, 部屋の奥行きが画面を埋める距離)`。
幅だけを見て引くと縦持ちで画面の下半分が部屋の外になり、
奥行きだけを見て寄ると横持ちで部屋の左右が切れる。
- **30fps で止める。** 描画だけでなく予測もこのゲートの内側で回す
  （描画だけ間引いても CPU は休まない）

HUD に fps / draw calls / tick / 補正回数が出る。

## サーバとのやりとり

送るのは**進みたい向きだけ**。座標は送れない（[09 §5.1](../docs/design/09-protocol.md)）。

```js
{ t:'intent', dx:-1, dy:0, seq:41 }      // 10Hz
```

受け取った tick で自分の位置を照合する。

- ずれが 0.55 タイルを超えたら**即座に合わせる**（HUD の「補正」が増える）
- 超えなければ毎 tick 25% ずつ寄せる。
  溜めてから跳ぶと画面が飛ぶので、溜まる前に消す

他人の位置は 10Hz の tick を 30fps に伸ばして補間する。
