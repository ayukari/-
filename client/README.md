# client — 実物のクライアント（3D / 2D）

**実サーバ（[../server/](../server/)）に WebSocket でつながる、動くクライアント。**
[../prototype/](../prototype/) が単体で完結した操作プロトタイプなのに対し、
こちらは**位置の正がサーバにある**。手元の座標は予測にすぎない。

```bash
cd ../server && npm install && npm run dev
# → http://127.0.0.1:8787/
```

複数人を試すときは別タブで名前を変えて開く。

```
http://127.0.0.1:8787/?name=あかり&body=0
http://127.0.0.1:8787/?name=そら&body=2
http://127.0.0.1:8787/?name=みなと&view=2d   ← 2D ビューを強制
```

> ★ `?u=` `?name=` で本人を名乗れるのは**開発用の仮認証**である。
> 本番は OIDC（[security-review-pack/02 §7](../docs/security-review-pack/02-data-flow.md)）で、
> 差し替えるのは `server/src/adapters/wsServer.js` の1箇所だけで済むようにしてある。

## 配線

依存は外→内の一方向。逆向きの矢印は無い（[08. 拡張のしかた](../docs/design/08-extensibility.md)）。

```
          /core/*.js            ← サーバと同一ファイル。移動の規則はここにしか無い
             ▲
        src/world.js            論理レイヤー。2Dグリッド上の事実だけ
             ▲        ▲            Three.js も DOM も知らない
   src/render3d.js  src/render2d.js    表現レイヤー。world を読むだけ・書かない
   src/net.js                       トランスポート。ここだけが WebSocket を知る
             ▲
        src/app.js              組み立て口。どの実装を使うかを知る唯一の場所
```

### `/core/` を共有しているのはなぜか

`client/src/world.js` は `/core/movement.js` を読み込む。
これは**サーバが権威判定に使っているのと同じファイル**を、dev サーバがそのまま配っている。

移動の規則が2つ存在すると、予測と権威がずれて「歩いていたら引き戻される」が常態化する。
実装を1つにすれば、ずれる余地は RTT の分しか残らない。

### 何ができるかは論理レイヤーが決める

ボタンの文言も、3D の光る輪も、`world.actionable()` の戻り値1つを見ている。
動詞は **sit / stand / use / knock / walk** の5つだけ（[08 §3](../docs/design/08-extensibility.md)）。

```js
world.actionable()
// → { verb:'sit',   object: <seat> }    席のタイルの上にいる
// → { verb:'use',   object: <note> }    手が届く
// → { verb:'knock', actor: <person> }   近くにいて、集中中でない
// → { verb:'walk',  object: <seat> }    席は見えているが、まだ上に乗っていない
```

**ここがサーバの検証と同じ条件を持っていないと壊れる。**
実際、最初の実装は「手が届けば座れる」にしていたため、ボタンは「ここに座る」と出るのに
サーバは必ず `denied` を返していた（サーバは席のタイルの**上にいること**を求める。[09 §5.2](../docs/design/09-protocol.md) ①）。
この食い違いは単体テストでは出ず、**2つ繋いで動かして初めて見つかった**ので、
[`server/test/gateway.e2e.test.js`](../server/test/gateway.e2e.test.js) に回帰試験を置いてある。

## 3D と 2D

`app.js` が起動時に一度だけ選ぶ。選んだあとの違いは**見え方だけ**で、論理も通信も同じ。

| 条件 | 起動するもの |
| --- | --- |
| 既定 | `render3d.js`（Three.js 0.186、自己ホスト） |
| WebGL が無い | `render2d.js` に自動で切り替え、その旨を表示 |
| `?view=2d` | `render2d.js` を強制 |

これが「**3D は採用するが必須にしない**」（[10 §9](../docs/design/10-assets.md)）の実体である。

### 描画予算を守るための実装

- 影なし・ポストエフェクトなし。`MeshLambertMaterial` + 半球光 + 平行光の2灯
- 通行不可タイルは `InstancedMesh` 2つ（外周の壁／内側の什器）に畳む
- オブジェクトは種別ごとに `InstancedMesh` 1つ
- アバターは1人あたり 本体・頭・鼻・名札 の4つ。**人数にしか比例しない**
- カメラは固定の斜め見下ろし。回転させない（3D酔いの主因）。
  縦持ちのときは引くのではなく**角度を立てる**（引くと空だけが増える）
- **30fps で止める。** 描画だけでなく予測もこのゲートの内側で回す
  （描画だけ間引いても CPU は休まない）

HUD に fps / draw calls / tick / 補正回数が出る。

## サーバとのやりとり

送るのは**進みたい向きだけ**。座標は送れない（[09 §5.1](../docs/design/09-protocol.md)）。

```js
{ t:'intent', dx:-1, dy:0, seq:41 }      // 10Hz
```

受け取った tick で自分の位置を照合する。

- ずれが 0.55 タイルを超えたら**即座に合わせる**（HUD の「補正」が増える）
- 超えなければ毎 tick 25% ずつ寄せる。
  溜めてから跳ぶと画面が飛ぶので、溜まる前に消す

他人の位置は 10Hz の tick を 30fps に伸ばして補間する。

## まだ本物でないもの

| 項目 | いまの状態 |
| --- | --- |
| 認証 | クエリ文字列の仮実装。**本番前に必ず差し替える** |
| 音声・映像 | 無い。`sit` は「通話中」フラグが立つだけ |
| フォーカスカード | 無い。プロトタイプ側にはある |
| ホワイトボード | オブジェクトはあるが、開いても何も出ない |
| アセット | すべてプリミティブ。glTF は未着手（[10. 3Dアセット仕様](../docs/design/10-assets.md)） |
| バイナリプロトコル | JSON のまま。仕様どおり**最後にやる**（[09 §10](../docs/design/09-protocol.md)） |
| フロア | `office` 1つだけ |
