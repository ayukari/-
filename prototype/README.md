# 操作プロトタイプ

`index.html` の1ファイルだけで動きます。ビルド不要。ブラウザで開いてください。

**公開版**: https://claude.ai/code/artifact/ba1caabc-6311-47c7-9135-83dd27756a46

```bash
# ローカルで開く場合
open prototype/index.html      # macOS
```

## できること（L0–L7）

画面左上の **「できること L0–L7」** で、いまこのビューで何が生きているかが見られます。

| 段 | 内容 | 本物かどうか |
| --- | --- | --- |
| L0 | 歩く・近づく・座る・ノック | 本物 |
| — | **WebGL 非対応端末での 2D 自動起動** | **本物**（`--disable-3d-apis` で検証済み） |
| L1 | 貼り紙・チームのボード・案内板・観葉植物 | 本物 |
| L2 | ドアと複数フロア（部屋 ⇄ ラウンジ） | 本物 |
| L3 | **実際のマイク** | **自分のマイクは本物**。相手の音声は SFU が要る |
| L4 | **他の人がリアルタイムに動く** | **本物**（同じページを2人以上で開くと見えます） |
| L5 | ホワイトボード | 本物。線は共有・永続 |
| L6 | 会議室の予約 | 本物 |
| L7 | ホワイトボードの E2EE | **本物**（AES-GCM）。ただし鍵配布は簡略 |

### L4 を試すには

**同じURLを2つのタブ、または別の端末で開いてください。** もう一方のアバターが実際に動きます。
下部バーの「◯人が接続中」で確認できます。

### L7 を確かめるには

ホワイトボードを開いて何か描き、右上の **「実データ」** を押してください。
共有ストアに保存されている中身（暗号文）がそのまま表示されます。

## 何を試せるか

| 流れ | 内容 |
| --- | --- |
| 1. アバターを作る | 名前・体型・色。3Dプレビューが即座に変わる |
| 2. チームに入る | チームごとの部屋。在室人数と「詰まり」件数が入る前に見える |
| 3. 部屋に入る | 3D空間を歩き、同僚に近づき、席に座って通話を始める |

### 操作

| | PC | スマホ・タブレット |
| --- | --- | --- |
| 移動 | `WASD` / 矢印キー、クリックした場所へ歩く | **タップした場所へ歩く。指を置いたまま動かすと追いかける** |
| 使う（着席・ノック・貼り紙を読む） | `E` | 右下の**丸ボタン**（表示が状況で変わる） |
| 離席 | 下部バーの「席を立つ」 | 丸ボタン「立つ」 |
| 今週のカード / メンバー | 右パネル（常時表示） | 下部バーの**「今週」で下から出るシート** |
| 表示切替 | 左上の 3D / 2D / リスト | 同じ（左上、コンパクト表示） |

スマホは縦画面を想定し、カメラの見下ろし角を強めて画面に部屋が収まるようにしてある。
描画解像度もタッチ端末では 1.25x に抑えている（[02 §6.4](../docs/design/02-problem-solving.md) の解像度スケーリング）。

## 設計のどこを実演しているか

## これは何ではないか

正直に分けておきます。

**本物**: マイクの取得（`getUserMedia`）/ 他の人の位置 / ホワイトボードの共有と永続化 /
E2EE（AES-GCM）/ 会議室の予約

**本物ではない**:

- **相手の音声** — SFU が要ります（[04 §5](../docs/design/04-architecture.md)）。自分のマイクだけが本物です
- **サーバ権威** — いまは各クライアントが自分の座標を主張しています。座標偽装は防げません
  （[04 §5.3](../docs/design/04-architecture.md) の対策は未実装）
- **鍵配布** — E2EE の鍵はボードIDから導出しています。実運用では Gateway が参加者にだけ配ります
  （[07 §4](../docs/design/07-security.md)）。示せているのは仕組みであって鍵配布の安全性ではありません
- **認証** — 誰でも同じ部屋に入れます
- **同僚のNPC** — 台本どおりに動くだけです
- **3Dアセット** — すべてコード内のプリミティブです

実測が必要なもの（低スペック実機での fps、E2EE の負荷、TURN の疎通）は
[06. ロードマップ](../docs/design/06-roadmap.md) の Phase 0 で扱います。

## コードの構造

[08. 拡張のしかた](../docs/design/08-extensibility.md) の配線をそのまま実装している。
1ファイルだがセクションで層が分かれており、**依存は常に外→内**。

```
core      World（グリッド・当たり判定・近接） / Registry（できることの登録簿）
systems   movement / conversation / interaction / presence
ports     SpaceRenderer（契約）
adapters  ThreeRenderer / FlatRenderer(2D) / ListRenderer / InputAdapter / Ui
boot      合成ルート。全部を知っているのはここだけ
```

状態の置き場所は3つに分けてある。

| 置き場所 | 何を | 購読 |
| --- | --- | --- |
| `World` | 座標（毎フレーム変わる） | しない。レンダラが直接読む |
| `Store` | ステータス・会話・表示モード | UI が購読 |
| `Bus` | 座った・ノックした（一回きりの出来事） | UI が受けてトーストを出す |

### 拡張点

オブジェクト種別を `Registry.define()` に1件足すと、**3D・2D・リストすべてに出る**。

```js
Registry.define('note', {
  action({obj}) { return { label:'読む', sub:'貼り紙', run: () => Ui.overlay(...) } },
  build3d(obj, mat, THREE) { /* 3D */ },
  draw2d(obj, ctx, transform) { /* 2D */ },
  listRow(obj) { /* リスト */ },
})
```

いま入っているのは `seat`（席）/ `note`（貼り紙）/ `board`（チームの今週ボード）の3種類。
相互作用の動詞は **「使う」1つだけ**（PC は `E`、スマホは丸ボタン）。
何が起きるかは `Systems.interaction.resolve()` が決め、UI はその戻り値しか見ない。

## 技術

- Three.js r128（CDN、UMD）
- 依存はこれだけ。ビルドツールなし
- 論理は 24×16 のグリッド。当たり判定・エリア判定・近接判定はすべてグリッド上で行い、描画方式に依存しない
