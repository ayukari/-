# tools

## `preflight.html` — 接続診断ツール

導入前に **「あなたの会社のネットワークで動くか」** を判定する単体 HTML。
[03. 機能要件 M-19](../docs/design/03-features.md) / [02 壁5](../docs/design/02-problem-solving.md) の成果物。

### 使い方

1. 自社の Web サーバに置く（**`https://` で配信すること**）
2. 社内の端末からブラウザで開く
3. 「診断を開始」を押す（20〜40秒）
4. 「レポートを印刷 / PDF 保存」で情シスに渡せる形にする

接続先は画面の「接続先の設定」か、URL のクエリで差し替える。

```
preflight.html?ws=wss://rt.example/probe
              &stun=stun:stun.example:3478
              &turn=turns:turn.example:443?transport=tcp
              &turnuser=USER&turnpass=PASS
              &dl=/probe-2mb.bin
```

### 判定する7項目

| 項目 | 見ているもの |
| --- | --- |
| ブラウザ | WebRTC と WebSocket への対応 |
| HTTPS | 安全なコンテキストか（WebRTC の前提） |
| WebSocket | 443/TLS の接続が**3秒維持されるか**（SSL インスペクションは確立直後に切ることがある） |
| UDP | STUN で反射アドレス（srflx）が取れるか |
| **TURN / TCP 443** | UDP が塞がれていても中継（relay）候補が取れるか。**ここが通れば通話は成立する** |
| 往復遅延 | WebSocket のエコー往復（中央値） |
| 推定帯域 | 既知サイズのファイルの取得時間から概算 |

### 総合判定

| 条件 | 判定 |
| --- | --- |
| WebSocket ✅ かつ（UDP ✅ または TURN ✅） | **利用できます** |
| WebSocket ✅ だが両方 ❌ | **通話以外は利用できます**（テキストモード） |
| WebSocket ❌ | **利用できません** |

「UDP が通らない＝使えない」にならないのが要点。
[01 §1.2](../docs/security-review-pack/01-endpoints.md) の通り、TURN over TCP/443 が本命の経路である。

### 必要なサーバ側の用意

| 用途 | 要件 |
| --- | --- |
| WebSocket の診断用エンドポイント | 接続を受け付け、**受信したメッセージをそのまま返す**（往復遅延の測定に使う）。エコーしない場合、遅延は「未測定」になる |
| 帯域測定用のファイル | 2MB 程度の静的ファイル。同一オリジン推奨。無ければ「未測定」になる |

### 設計方針

- **外部依存ゼロ。** CDN もフォント配信もライブラリも使わない
  （[審査パッケージ 01 §4](../docs/security-review-pack/01-endpoints.md) で決めた方針に、この道具自身が従う）
- PDF 化はブラウザの印刷機能（`window.print()` + 印刷用スタイル）。ライブラリを足さない
- **端末情報・音声・入力を一切送信しない。** マイクやカメラの許可も求めない
- ダークモード対応

### 制約

- **Claude のアーティファクトとして公開しても動かない。** CSP が外部への WebSocket と
  fetch を塞ぐため、`file://` またはアーティファクト上では正しい判定にならない
- `file://` で開くと帯域測定ができず、HTTPS 項目が「注意」になる

### 動作確認の状況

- 到達しない接続先を与えた場合の挙動（不可 / 注意 / 未測定の出し分け、総合判定）は確認済み
- **実在するサーバに対する OK 判定は未確認。** 診断用エンドポイントが立ってから検証する
