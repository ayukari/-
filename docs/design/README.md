## この設計の要点

- **フォーカスカード**（今週やること3〜5件の宣言）が中核であり、空間・会議室はその周辺装置である
- **「作らない」判断が多い**（自動通話・稼働ログ・録画・影/ポストエフェクト・ネイティブアプリ）。
  それぞれが複数の壁に同時に効いているので、実装中に安易に覆さないこと
- 空間を捨てても（リストモード）、通話を捨てても（テキストモード）、プロダクトが成立する構成にしてある
- **拡張点は `Registry` 1箇所**。オブジェクト種別を足すと 3D / 2D / リストすべてに出る。
  相互作用の動詞は「使う」1つに保つ
- **接続の安全性の弱点は SFU 1箇所**。そこに E2EE・セルフホスト・プライベートルームでの E2EE 強制を重ねる。
  TURN リレーは中身を見られず、P2P にしていないので参加者同士に IP も渡らない
- **3D 空間を採用する（2026-09-13 決定）。** ただし **論理レイヤー（2Dグリッド）と表現レイヤーを分離**し、
  3D → 2D ビュー → リストモードへ縮退できるようにしてある。**3D は採用するが必須にはしない。**
  実機ベンチの前に決めたため、縮退経路が唯一の担保になっている（[10 §9](./10-assets.md)）
