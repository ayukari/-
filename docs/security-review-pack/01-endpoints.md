# 01. 通信先とポート一覧

> 設計段階の記載。実装後に実測値で更新する（[README の注記](./README.md)）。

ネットワーク管理者が **許可リストにそのままコピーできる形** で書く。
ドメイン名は仮のもの（`example` の部分が実際のドメインに置き換わる）。

---

## 1. SaaS 形態

### 1.1 許可が必要な通信（クライアント → 外向き）

| # | 用途 | ホスト | プロトコル / ポート | 必須 |
| --- | --- | --- | --- | --- |
| 1 | Web アプリ本体・API | `app.hidamari.example` | TCP 443 (HTTPS) | ✅ |
| 2 | リアルタイム同期（位置・状態） | `rt.hidamari.example` | TCP 443 (WSS) | ✅ |
| 3 | 音声・映像（SFU） | `sfu.hidamari.example` | **UDP 50000–60000** | 推奨 |
| 4 | 音声・映像の代替経路（TURN） | `turn.hidamari.example` | **TCP 443 (TLS)** | ✅ |
| 5 | 認証（顧客の IdP） | `accounts.google.com`<br>`oauth2.googleapis.com`<br>（または `login.microsoftonline.com`） | TCP 443 | ✅ |

**5行。** うち #5 は Google Workspace / Microsoft 365 を使っている組織なら**既に許可済み**なので、
実質追加は **4行**である。

### 1.2 #3 と #4 の関係（重要）

| 環境 | 動作 |
| --- | --- |
| UDP が通る | #3 を使う。低遅延 |
| **UDP が全面ブロック** | **#4 に自動フォールバック。443/TLS なので HTTPS と同じ見え方**。遅延は増えるが通話は成立する |

**#3 を許可しなくても動く。** #4 が必須で #3 が推奨なのはそのためである。
「UDP は開けられない」と言われた時点で審査が止まらないようにしてある
（[02 壁5](../design/02-problem-solving.md)）。

### 1.3 使わないもの（明示しておくと質問が減る）

| 項目 | 状況 |
| --- | --- |
| 独自ポート | **使わない。** 443 と UDP 50000–60000 のみ |
| インバウンド通信 | **不要。** クライアントからの発信のみ。社内にポートを開けない |
| VPN / 専用線 | 不要 |
| 常駐エージェント・端末へのインストール | **なし。** ブラウザのみ |
| 管理者権限 | **不要** |
| CDN | **使わない**（§4） |
| 解析・トラッキング SaaS | **使わない**（§4） |

## 2. セルフホスト形態

顧客のネットワーク内に設置する。**外向き通信は認証だけになる。**

### 2.1 許可が必要な通信

| # | 用途 | ホスト | プロトコル / ポート |
| --- | --- | --- | --- |
| 1 | 認証（顧客の IdP） | 顧客の IdP | TCP 443 |

**1行。** それ以外の通信はすべて社内で完結する。

### 2.2 社内に必要なサーバ

構成は WorkAdventure の公開されている自ホスト要件を参考にしている
（同じ LiveKit + coturn 構成のため）。

| サーバ | 役割 | 規模の目安 | 公開IP / DNS |
| --- | --- | --- | --- |
| アプリ | Web・API・リアルタイム同期・DB・Redis | 2 vCPU / 4GB〜 | 社内向けで足りる |
| **SFU（LiveKit）** | 音声・映像の中継 | **メディアを扱うため、ここが一番要る** | 必要 |
| **TURN（coturn）** | UDP 不可の端末の中継 | 帯域が要る | **必要**（TCP 443 を占有するため別ホスト） |

> WorkAdventure の文書では、アプリ本体は 2 CPU / 4GB で同時 300 人程度まで、
> **coturn と LiveKit は「はるかに強力なサーバが必要」**とされている。
> LiveKit の容量は「ルーム数や人数ではなく**購読トラック数**」で決まり、
> WebRTC は CPU グラフが危険に見える前に劣化するため **CPU に 30〜40% の余裕**を残す。

### 2.3 TLS 証明書

WebRTC は**有効な証明書を持つ HTTPS 接続を要求する**。
社内 CA の証明書でもよいが、**全端末に配布済みであること**が条件。
自己署名のままでは動かない。

→ 導入前チェックの項目に入れる（[05 Q17](./05-qa.md)）。

## 3. 帯域の見積もり

情シスが自分で計算できる形で出す。

```
1人あたり
  アイドル（フロアにいるだけ）        10 kbps 未満
  音声通話中                          40 kbps
  低帯域モード（Opus 16kbps）         20 kbps
  テキストモード（通話しない）         5 kbps
  ビデオ通話中（会議室でONにした時）   600 kbps〜
```

```
100人の組織 / 平均20%が同時通話の場合
  アイドル 80人 × 10 kbps =  0.8 Mbps
  通話中   20人 × 40 kbps =  0.8 Mbps
  ─────────────────────────────────
  合計                    ≒ 1.6 Mbps
```

**「ビデオ会議ツール」から想像される帯域より1桁小さい。**
既定でビデオ OFF（[03 非機能要件](../design/03-features.md)）がそのまま説得材料になる。

支店から本社へ VPN 集約している構成では、この値 × 支店人数が本社の外向き帯域に乗る。
**その場合はセルフホストを勧める**（社内で完結するため外向き帯域を消費しない）。

## 4. 外部依存を持たない方針（設計変更あり）

許可リストの行数を増やさないため、次を**すべて自ホストする**。

| 項目 | 当初の設計 | 変更後 |
| --- | --- | --- |
| **Web フォント** | `fonts.googleapis.com` / `fonts.gstatic.com` から読む | **自ホストの woff2 に変更** |
| JS ライブラリ | CDN | 自ホスト（バンドルに含める） |
| 3Dアセット | — | 自ホスト（元から） |
| アイコン | — | インライン SVG |
| 解析・エラー収集 | 未定 | **外部 SaaS を使わない。** 必要ならセルフホスト版 |

> **これは審査対応のために設計を変えた箇所である。**
> フォントを外部から読んでいると、セルフホスト形態で「外部通信は認証だけ」と言えなくなる。
> 見た目の都合より、[02 壁5](../design/02-problem-solving.md) の
> 「許可リスト5行以内」を優先した。
>
> なお `prototype/index.html` は CDN のフォントと Three.js を使っている。
> **試作は試作であり、この方針の対象外**である。製品版で自ホストに切り替える。

**依存を1つ増やすたびに、セルフホストの価値と許可リストが1行ずつ悪化する。**
新しい外部依存を入れるときは、この表を更新してから入れる。
