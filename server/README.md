# server — サーバ側の中核ロジック（Phase 1）

**[09. ワイヤプロトコル仕様](../docs/design/09-protocol.md) §5「サーバ権威の検証規則」の実装。**

同仕様 §10 が実装順を指定している。

> 1. チャネル B だけで動かす（JSON で座標も送る。遅くてよい）
> 2. **§5.1・§5.2 の検証を入れる ← ここが本体。先に正しくする**
> 3. §6 の巻き戻し照合を入れる
> 4. 最後に §3 のバイナリ化と §3.5 の AOI で速くする
>
> **最適化は最後。検証が正しくないバイナリ実装には価値がない。**

いまは **2 まで** が入っている。さらに、実際に動かすための
**WebSocket アダプタと開発用サーバ**が乗っている。

```bash
npm install
npm run dev   # http://127.0.0.1:8787/ — 実物のクライアント（../client/）が開く
npm test      # 87件。core と gateway は依存0、通しの試験だけ ws を使う
```

## 構造

依存は常に外→内（[08. 拡張のしかた](../docs/design/08-extensibility.md)）。

```
src/core/        盤面の規則。純粋。DOM も DB も WebSocket も知らない
  grid.js          当たり判定・エリア・オブジェクト（タイル単位）
  movement.js      速度上限と壁ずり           ← 09 §5.1
  proximity.js     近接判定（集中中・離席を除外）← 00 原則2
  seats.js         着席の4条件                ← 09 §5.2
src/gateway/     規則を時間で進める。トランスポートを知らない
  room.js          フロア、tick、AOI、差分抑制  ← 09 §3.5 / §3.6
  session.js       1接続分の状態と権限判定      ← 09 §2 / §5
  protocol.js      チャネル B の検証            ← 09 §4
  ratelimit.js     トークンバケット             ← 09 §5.3
  violations.js    違反の計数（★永続化しない） ← 09 §5.4
src/world.js     フロア定義と、組織×フロアの部屋の管理
src/adapters/    ここだけが外の世界を知る
  wsServer.js      HTTP 静的配信 + WebSocket + 10Hz の tick ループ
src/main.js      開発用の起動口
```

`Session` と `Room` はトランスポートを知らないまま変えていない。
`wsServer.js` は `Session.handle()` の戻り値（`{out, to, broadcast, close}`）を
実際の送信に変えるだけの薄い層で、**そこにしか WebSocket は出てこない**。

### ブラウザにも `src/core/` を配っている

`/core/*.js` は `src/core/` をそのまま配信している。
クライアントは**サーバが権威判定に使っているのと同じ `movement.js`** で自分の動きを予測する。
移動の規則を2つ持たないためで、これが無いと予測と権威が構造的にずれる。

### 通しの試験（`test/gateway.e2e.test.js`）

実際に HTTP と WebSocket を立てて2人つなぐ。**単体テストでは出ない種類の穴**を見る。

| テスト | 守っている性質 |
| --- | --- |
| フロア定義が HTTP で配られる | 当たり判定の正はサーバにあり、クライアントは受け取るだけ |
| `/vendor/..%2F..%2F` が通らない | パストラバーサル |
| `/core/movement.js` が配られている | 移動の規則が2つ存在しない |
| 2人つなぐと互いが名簿に出て位置が届く | |
| 向きだけで動き、外周の壁を抜けられない | 09 §5.1 |
| **席のタイルの上にいるときだけ座れる** | 09 §5.2 ①。下記参照 |
| 近くなら声をかけられ、集中中・遠距離では届かない | 00 原則2 |
| 切断すると名簿から消える | |

### 権限と偽装

| テスト | 守っている性質 |
| --- | --- |
| クライアントが `orgId` を偽装しても、セッションの値が使われる | [09 §2](../docs/design/09-protocol.md)。他組織の部屋に入れない |
| 余計なフィールドは落とされる（`orgId` / `userId` / `isAdmin`） | 同上。スキーマに無い値は通らない |
| 離れた席には座れない | [09 §5.2](../docs/design/09-protocol.md) ①。座標はサーバの値を使う |
| 離れた相手にはノックできない | 同上 |
| 手が届かないオブジェクトは使えない | 同上 |
| プロトタイプ汚染が効かない | `__proto__` を送っても `Object.prototype` を汚さない |

### 移動の検証

| テスト | 守っている性質 |
| --- | --- |
| 速度上限を超えて進めない | [09 §5.1](../docs/design/09-protocol.md) |
| `dt` を大きく偽装しても 250ms 相当までに丸められる | 一括テレポートの防止 |
| `dx/dy` を 1 より大きく偽装しても効果がない | |
| NaN / Infinity / 文字列を送っても壊れない | |
| 壁は抜けられない / 外周の外に出られない | |
| 壁ずり: 斜めに壁へ向かっても進める軸は進む | 斜めで完全に止まらない |

### 設計原則

| テスト | 守っている性質 |
| --- | --- |
| 「集中中」「離席」は近接の対象にならない | [00 原則2](../docs/design/00-overview.md) |
| 集中中の相手にはノックが届かない | 同上 |
| 集中中にすると席を立ち、通話が切れる | 原則1と原則2の整合 |
| **違反の記録に永続化の経路が無い** | [00 原則3](../docs/design/00-overview.md)。`violations.js` のコードを走査し、`audit` / `prisma` / `writeFile` などが現れたら落ちる |
| 走査はコメントを無視してコードだけを見ている | 上の保護自体が壊れていないことの確認 |
| 拒否の理由が条件ごとに違わない | 存在の推測に使わせない |
| 運用監視に出せるのは総数だけ | 個人も組織も持たない |

## テストが見つけた実際のバグ

**`ViolationCounter` と `TokenBucket` が `0` を「未設定」の番兵に使っていた。**

```js
this.last = 0;
...
if (this.last !== 0) { /* 減衰処理 */ }
```

`nowMs = 0` で呼ばれると、時刻を記録したのに「未設定」と誤判定され、**減衰が一切効かない**。
テスト環境では時刻 0 から始めることが多いので見つかったが、
本番でも単調時計の起点次第で踏みうる。`null` を番兵に変更した。

**仕様書を書いただけでは見つからなかった。** テストを書いたら落ちた。

## アセットのテストが見つけた実際のバグ

**glTF エクスポータが頂点カラーのアルファを落とし、全員が同じ色で立っていた。**

着せ替えは「頂点カラーのアルファに部位IDを入れ、クライアントが塗り替える」方式にしてある。
ところがエクスポータは、マテリアルがアルファを使っていないと COLOR_0 を VEC3 に落とす。
部位IDが消え、塗り替えが一人も効かなくなる。

**画面には出ていた。3人とも同じ服を着て立っていただけで、エラーは1つも出ない。**
名簿の色（オレンジ・青緑・紫）と見比べて初めて気づいた。
いまは `assets.test.js` が VEC4 であることと、部位ID 0〜5 が揃っていることを検査する。

## 通しの試験が見つけた実際のバグ

**クライアントが「ここに座る」を出せるのに、サーバが必ず断る状態になっていた。**

クライアントは「手が届く範囲（1.5タイル）」でボタンを出していたが、
サーバは [09 §5.2](../docs/design/09-protocol.md) ① で **その席のタイルの上にいること**を求める。
押せるのに毎回 `denied` が返る。

単体テストは両方とも通っていた。**どちらも仕様どおりで、仕様の解釈が2箇所で違っただけ**なので、
2つ繋いで動かすまで誰も気づけない。判定をクライアントの論理レイヤー（`world.actionable()`）に
1箇所化し、通しの試験で固定した。
